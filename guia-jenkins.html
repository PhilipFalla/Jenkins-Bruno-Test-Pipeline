Pipeline CI/CD en Jenkins con Bruno como puerta

La suite bruno/smoke corre en un job Freestyle armado a mano en la interfaz. La suite bruno/regresion corre en un Jenkinsfile en Groovy, en el repositorio de la HDT 4, y funciona como puerta: si pasa, construye la imagen del API y la despliega en el contenedor books-api, puerto 8001. Si falla una aserción, no hay imagen ni despliegue. Cada commit en GitHub dispara el pipeline.

b. Jenkins

Containerfile

Guardar como jenkins-lab/jenkins/Containerfile:

# Jenkins LTS con bru (Bruno), uv con Python 3.12 y el CLI de docker.
# El CLI de docker habla con el motor del host por el socket montado en
# /var/run/docker.sock; sirve igual con Podman y con Docker Desktop.
# Sin USER jenkins al final: corre como root para poder usar ese socket.
FROM docker.io/jenkins/jenkins:lts-jdk21

USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends nodejs npm \
 && rm -rf /var/lib/apt/lists/* \
 && npm install -g @usebruno/cli \
 && bru --version

COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /usr/local/bin/
COPY --from=docker.io/library/docker:cli /usr/local/bin/docker /usr/local/bin/
ENV UV_PYTHON_INSTALL_DIR=/opt/uv-python
RUN uv python install 3.12 && chmod -R a+rX /opt/uv-python
cd jenkins-lab
podman build -t jenkins-bruno jenkins

Contenedor

SOCK=$(podman info --format '{{.Host.RemoteSocket.Path}}' | sed 's|unix://||')
podman volume create jenkins_home
podman run -d --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v "$SOCK":/var/run/docker.sock \
  --security-opt label=disable \
  jenkins-bruno
  • $SOCK es el socket de Podman dentro de la VM, por ejemplo /run/user/501/podman/podman.sock. Montado en /var/run/docker.sock, Jenkins construye y corre contenedores en el mismo motor que el propio Jenkins.
  • --security-opt label=disable: SELinux de la VM bloquea el socket sin esta opción (permission denied).
  • El contenedor corre como root para poder abrir el socket. En Podman rootless, ese root es el usuario de la VM y no el root de la Mac. Aceptable en un laboratorio local, no en un servidor compartido.
  • Docker Desktop: sin SOCK ni --security-opt, con -v /var/run/docker.sock:/var/run/docker.sock.
Si ya existe el contenedor jenkins de una versión anterior de esta hoja: correr el podman build de arriba, luego podman rm -f jenkins y el podman run sin el podman volume create. Jobs, usuarios y credenciales viven en el volumen jenkins_home y se conservan; Jenkins no pide el asistente otra vez.

Comprobar que Jenkins ve el motor:

podman exec jenkins docker ps      # lista los contenedores, incluido jenkins

Desbloqueo y asistente (solo con volumen nuevo)

podman exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
  1. Pegar la clave en localhost:8080.
  2. Install suggested plugins. Trae Pipeline, Git, JUnit, Credentials y Pipeline Graph View, que dibuja las etapas del build.
  3. Crear el usuario admin y dejar http://localhost:8080/ como URL.

d. Archivos del repo

Containerfile del API

En la raíz del repositorio. El __main__ de api.py escucha en 127.0.0.1, que dentro de un contenedor no se alcanza desde afuera, así que la imagen arranca uvicorn en 0.0.0.0.

FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen
COPY api.py .
EXPOSE 8000
CMD ["uv", "run", "--frozen", "uvicorn", "api:app", "--host", "0.0.0.0", "--port", "8000"]

Jenkinsfile

En la raíz, con el nombre Jenkinsfile. Commit y push.

// CI: arranca el API y corre la regresion. bru sale con 1 si falla
// una aserción, la etapa queda roja y las siguientes no corren.
// CD: solo con la regresion en verde, imagen nueva y books-api reemplazado.
pipeline {
  agent any
  triggers { pollSCM('H/2 * * * *') }
  options {
    skipDefaultCheckout()
    timeout(time: 15, unit: 'MINUTES')
  }
  environment { IMAGE = "books-api:${env.BUILD_NUMBER}" }
  stages {
    stage('Checkout') {
      steps { checkout scm }
    }
    stage('Start API') {
      steps {
        sh '''
          nohup uv run api.py > api.log 2>&1 &
          echo $! > api.pid
          for i in $(seq 1 60); do
            curl -sf http://127.0.0.1:8000/health && exit 0
            sleep 1
          done
          cat api.log; exit 1
        '''
      }
    }
    // --sandbox=developer: el sandbox por defecto de bru falla al azar bajo carga.
    stage('Regresion') {
      steps {
        dir('bruno/regresion') {
          sh 'bru run --env local --sandbox=developer --reporter-junit results.xml'
        }
      }
    }
    stage('Build image') {
      steps { sh 'docker build -f Containerfile -t "$IMAGE" .' }
    }
    stage('Deploy') {
      steps {
        sh '''
          docker rm -f books-api || true
          docker run -d --name books-api -p 8001:8000 "$IMAGE"
          for i in $(seq 1 30); do
            docker exec books-api python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')" && exit 0
            sleep 1
          done
          docker logs books-api; exit 1
        '''
      }
    }
  }
  post {
    always {
      junit allowEmptyResults: true, testResults: 'bruno/regresion/results.xml'
      sh 'kill "$(cat api.pid)" 2>/dev/null || true'
    }
  }
}

El API de las pruebas corre dentro de Jenkins en el puerto 8000. El desplegado es un contenedor aparte, books-api, publicado en el 8001 de la máquina propia.

e. Job CI/CD

New Item → hdt5-cd → Pipeline → Definition: Pipeline script from SCM:

CampoValor
SCMGit
Repository URLhttps://github.com/USUARIO/REPO.git
Credentialsgithub-pat si el repositorio es privado (sección f); none si es público
Branch Specifier*/main (el valor por defecto es */master)
Script PathJenkinsfile
  1. Save → Build Now una vez. Jenkins registra el pollSCM al leer el Jenkinsfile en ese primer build; antes de eso ningún commit dispara nada.
  2. Abrir el build → Stages: las cinco etapas en verde. Desde la Mac, curl localhost:8001/health responde {"status":"ok","books":3}.
  3. De ahí en adelante, Jenkins revisa GitHub cada 2 minutos (H/2 * * * *) y corre un build por cada commit nuevo en main. La consola de ese build empieza con Started by an SCM change y trae la línea Checking out Revision <SHA>.

Un webhook de GitHub no llega a un Jenkins en localhost sin un túnel; por eso el disparador es polling.

f. Repositorio privado

  1. GitHub: Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Solo el repositorio de la HDT 4, permiso Contents: Read-only.
  2. Jenkins: Manage Jenkins → Credentials → System → Global credentials → Add Credentials. Kind: Username with password; usuario de GitHub, el token como contraseña, ID github-pat.
  3. Elegir github-pat en Credentials del job.
El token no va en ningún archivo del repositorio.

Build bloqueado

  1. Cambiar una aserción de bruno/regresion/ para que sea falsa, por ejemplo res.status: eq 200 por eq 201. Commit y push: el polling dispara el build, que termina en FAILURE. Captura 02, y sirve también para la 03.
  2. git revert HEAD y push. El último build queda en verde y books-api sigue respondiendo en el 8001.

Los dos commits quedan en el historial, sin squash ni force push.

i. Limpieza

Pausar

podman stop jenkins books-api
podman machine stop
# para volver:
podman machine start && podman start jenkins books-api

Borrar el despliegue

podman rm -f books-api
podman rmi $(podman images --filter reference=books-api --format '{{.Repository}}:{{.Tag}}')

Borrar todo, después de entregar

podman rm -f jenkins books-api
podman volume rm jenkins_home
podman rmi jenkins-bruno
podman machine stop && podman machine rm -f
